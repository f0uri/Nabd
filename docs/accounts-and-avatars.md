# إصلاح الصورة الشخصية ويوزر الحساب

## السلوك الجديد

- روابط الصور النسبية (`/media/...`) تتحوّل إلى روابط كاملة في تسجيل الدخول، واسترجاع الجلسة، والتسجيل، وتحديث الملف وقوائم المستخدمين. كذلك تُصلح الروابط النسبية في النسخة المحفوظة محليًا عند العمل دون إنترنت.
- قراءة قائمة منشورات تجريبية عند تعذر الخادم لا تغيّر مصدر المصادقة أو الكتابة. في وضع `auto` تسجيل الدخول والتسجيل واسترجاع الحساب وحفظ الملف تتصل بالخادم الحقيقي مباشرة. لا تُصنع جلسة تجريبية تلقائيًا عند فشل تسجيل الدخول، ولا يُستبدل الحساب المحفوظ بـ `CURRENT_USER` أثناء انقطاع الشبكة.
- في وضع `mock` الصريح، تبقى تجربة تسجيل الدخول التجريبي ممكنة للتطوير، لكن حفظ الملف/الصورة مرفوض برسالة واضحة؛ لا نجاح وهمي ولا ادعاء رفع صورة لم تُرفع.
- رفع الصورة يعالج حالات HTTP والفشل وانتهاء مهلة 30 ثانية. بعد النجاح فقط تُحفظ بيانات المستخدم الراجعة من الخادم في تخزين الجلسة. لا يمسح هذا التحديث التخزين أو يسجل خروج المستخدم تلقائيًا.
- لكل حساب حقيقي `username` مستقل عن الاسم الظاهر. الأسماء الظاهرة يمكن تكرارها، لكن اليوزر لا يمكن تكراره حتى عند اختلاف حالة الأحرف أو تزامن الطلبات.
- القواعد: من 3 إلى 40 حرفًا، يبدأ بحرف إنجليزي، والباقي حروف إنجليزية أو أرقام أو `_`. يقبل الإدخال `@` في البداية ويُخزّن دونها وبأحرف صغيرة.
- المستخدم يغيّر اليوزر من **الملف الشخصي ← تعديل الملف**، ويراه تحت اسمه في الملف ونتائج البحث والأصدقاء. يمكن البحث بالاسم أو `@username`؛ البحث بـ `@` يستهدف اليوزر فقط، وتظهر المطابقة الكاملة أولًا.
- الحسابات القديمة تحصل على معرّف ثابت `u_` متبوعًا ببصمة ID، والحسابات الجديدة تحصل على معرّف مولّد يمكن تغييره من الملف. يمنع فهرس PostgreSQL الفريد وجود أي يوزرين متماثلين. لا تعتمد هوية الحساب على اسمه الظاهر ولا يتغير ID أو مرجع الصورة.

## حدود التفعيل — الخادم ليس جزءًا من OTA

لخيار نشر جاهز مع تلغرام وقرص دائم، راجع [دليل الوسيط والاستضافة](telegram-hosting.md).

**نشر تحديث الهاتف لا ينشر الخادم ولا قاعدة البيانات.** يجب نشر نسخة `server/` الجديدة على الاستضافة الحقيقية لكي تُتاح خاصية اليوزر وحفظ الصور بين الأجهزة.

1. خذ نسخة احتياطية من قاعدة البيانات ووسائط المستخدمين.
2. حدّث خدمة الخادم إلى كود هذا الإصدار وأعد تشغيلها، مع الحفاظ على `DATABASE_URL` أو مجلد PGlite الدائم، ومجلد الوسائط/إعدادات التخزين، و`AUTH_SECRET` الحالي. لا تستبدلها ببيانات تطوير جديدة.
3. عند الإقلاع ينفّذ `initDb()` إضافة العمود، وتعبئة اليوزرات القديمة، والفهرس الفريد، وشرط عدم null. إعادة التشغيل لا تغيّر اليوزرات المختارة ولا الصور. أوقف نسخ الخادم القديمة أثناء ترقية الكتابات؛ النسخة القديمة لا تعرف عمود `username` الإلزامي عند إنشاء حساب.
4. اضبط **GitHub Actions repository variables** على عنوان GraphQL العام الحقيقي: `NABD_API_URL=https://YOUR_REAL_HOST/graphql`، ويُنصح بـ `NABD_DATA_SOURCE=graphql`. `localhost` داخل APK يشير للهاتف نفسه وليس لاستضافتك. لم تُضبط هذه المتغيرات نيابة عن صاحب المستودع، ولا تتوفر هنا بيانات استضافة لنشر الخادم.
5. أعد نشر **App updates (OTA)** من `main` بعد ضبط العنوان. لا تضع مفاتيح Expo أو قاعدة البيانات ضمن المتغيرات العامة أو داخل التطبيق.
6. افتح التطبيق وافحص التحديث، ثم جرّب رفع صورة، وإغلاق التطبيق وفتحه، وتغيير اليوزر والبحث عنه من حساب آخر يحمل الاسم الظاهر نفسه.

### توافق خادم قديم

الإصدار الجديد يفحص وجود حقل `Author.username` ومعامل `updateProfile.username` باستخدام استعلام introspection واحد مشترك بين الطلبات في العملية. إذا كان الخادم قديمًا، لا تُرسل الحقول الجديدة له: تبقى وظائف الصورة والدخول والطلبات القديمة صالحة، ويظهر تنبيه أن اليوزر يحتاج تحديث الخادم بدل اختلاق يوزرات محلية. إذا كان introspection معطلًا، يستخدم التطبيق هذه الواجهة القديمة أيضًا. أخطاء الشبكة العابرة لا تثبّت غياب الميزة بصورة دائمة.

الخادم الجديد يقبل استدعاءات التسجيل والتعديل القديمة دون معامل `username`. لا يلزم تحديث APK بسبب هذه التعديلات؛ لم نضف مكتبات أصلية أو صلاحيات أو نغيّر Expo config أو lockfile. اختُبر تطابق fingerprint لكود الأساس وكود الإصدار في بيئة التبعيات والمسار نفسيهما. يظل اختبار الوصول على الهاتف الفعلي مطلوبًا.

### الحسابات التجريبية السابقة

الجلسات ذات التوكن التجريبي ليست حسابات محفوظة على خادم. هذا الإصلاح لا يحوّلها إلى حسابات حقيقية ولا يرفع بياناتها دون إذن. بعد ربط استضافة فعلية، يمكن للمستخدم تسجيل حساب حقيقي أو الدخول إلى حسابه الموجود. الصور التي لم تُرفع أصلًا في وضع Mock لا يمكن استرجاعها من الخادم؛ يجب اختيارها مجددًا وحفظها بعد الاتصال الصحيح.

## التحقق

```sh
npm ci --prefix mobile
npm run typecheck --prefix mobile
node --test mobile/tests/*.test.cjs
npm ci --prefix server
node --test server/tests/*.test.js
cd mobile && npx expo export --platform android
```

اختبارات الهاتف تنفّذ كود TypeScript الفعلي مع محاكاة الشبكة والتخزين. اختبارات الحسابات تستخدم نسخًا معزولة من كود الخادم وقاعدة PGlite دائمة مؤقتة: ترقية قاعدة قديمة، تكرار الأسماء، تصادم اليوزرات المتزامن، صلاحيات التعديل، رفع ملف إلى التخزين المحلي، وإعادة فتح القاعدة والكاش مع الحفاظ على الصورة واليوزر. لا تُستخدم بيانات أو أسرار مستخدمين حقيقية.
