# نبض: تلغرام مباشرة، بلا Render ولا خادم وسيط

هاد الوضع المؤقت كيستعمل **نفس نمط `f0uri/ahdaf`: ملف JSON مشترك مرفوع كمستند، وآخر نسخة مثبتة فمحادثة تلغرام**. التطبيق كيهضر مباشرة مع Bot API. ما كيشغّلش كود داخل تلغرام وما كيحتاجش Render أو استضافة Node. ما تنسخ حتى توكن أو بيانات من ahdaf.

```text
الهاتف → Telegram getMe/getChat → المستند المثبت
       → getFile → قراءة nabd-vault.json
       → تعديل محلي → sendDocument → pinChatMessage → إعادة قراءة للتأكيد
```

## حدود مهمة — قبل التفعيل

- **مفتاح البوت عمومي وقابل للاستخراج من APK أو OTA.** وضعه في GitHub Secrets كيحمي سجل البناء، ماشي التطبيق المشحون. الإخفاء والترميز ماشي تشفير.
- كل نسخة من التطبيق تقدر تقرا وتبدل **جميع** الحسابات والبريد والصور والمنشورات فـ JSON، وتنتحل أي حساب أو تعطل البوت. القناة الخاصة كتمنع الجمهور العابر فقط، ماشي المشاركين اللي عندهم نفس البوت.
- كلمات السر كتتحفظ بـ PBKDF2-SHA256، 210000 دورة وsalt مستقل مشتق من UUID أصلي؛ أسرار الجلسات كتتحفظ كتجزئات SHA256، والجلسة كتسالي بعد 30 يوم. هادشي كيقلل تخزين النص الصريح فقط: **ما كيخلقش مصادقة أو صلاحيات خادم موثوقة**. ممكن هجوم تخمين بلا اتصال، أو تعديل الملف لتجاوز الدخول بالكامل. استعمل كلمة سر تجريبية مختلفة عن باقي خدماتك وبريدًا غير حساس.
- طابور الكتابة محلي فقط. فحص الرسالة المثبتة قبل وبعد الرفع كيلتقط بعض التعارضات، **ماشي قفل موزع ولا كتابة ذرية**. جهازان يقدرا يضيعا تغيير متزامن أو يتجاوزا تفرد اليوزر. عند خطأ حفظ أو مهلة، عاود القراءة أولاً: ممكن تلغرام قبل التغيير ولكن التأكيد ما وصلش. ما تعاودش العملية بشكل أعمى.
- نسخ JSON القديمة كتبقى كاملة فالمحادثة للاسترجاع؛ حذف منشور أو تسجيل الخروج ما كيمسحش أثره من التاريخ. ما كاينش تشفير طرفي أو تحقق بريد أو استرجاع كلمة سر أو ضمان خدمة.
- حد النسخة **2 MiB**، وحد الصورة المحلية **128 KiB** (JPEG/PNG/WebP). تنزيل React Native كيخزّن الرد فالذاكرة قبل التحقق؛ فحص الحجم المسبق واللاحق ماشي حد ذاكرة streaming. مناسب غير لمجموعة صغيرة موثوقة، ماشي إطلاق عام.

## شنو خدام هنا؟

| الميزة | الوضع المباشر |
|---|---|
| إنشاء الحساب والدخول واسترجاعه من جهاز آخر | نعم، بنفس إعداد البوت والمحادثة، بلا إثبات هوية من خادم |
| الاسم/الصورة/النبذة/اليوزر والبحث بالاسم أو اليوزر | نعم، فنسخة JSON المشتركة |
| إضافة وإزالة صديق | نعم |
| منشورات عامة نصية أو بصورة صغيرة، تعليقات وتفاعلات وحذف | نعم، تعاد كتابة النسخة كاملة لكل تعديل |
| منشورات خاصة أو للأصدقاء فقط | مرفوضة صراحة؛ JSON ما يقدرش يضمن خصوصيتها |
| دردشة خاصة، ترجمة، فيديو، رفع/اختبار جلسة إنستغرام أو استيراد ريلز | غير متاح؛ الطلب يرجع خطأ واضح، بلا تحويل لخادم أو Mock |
| ريلز/إشعارات/شارات غير مقروءة | قوائم خاوية/عداد صفر، بلا بيانات تجريبية؛ التنبيه الدائم كيوضح أنها غير متاحة |
| الأدمن/التوثيق | ما كيتمنحوش فهاد الوضع |

أوضاع GraphQL وMock القديمة باقية. مخزن الجلسة المباشرة معزول حسب هوية البوت ومعرف المحادثة؛ ما كيتنقل حتى حساب قديم تلقائيًا وما كيتسيفط حتى توكن تلغرام لـ GraphQL أو WebSocket. تبديل توكن **نفس البوت** ما كيبدلش namespace، لكن تبديل البوت أو المحادثة كيعني مخزنًا منفصلًا.

## إعداد واحد، من الهاتف

1. أنشئ **بوتًا جديدًا خاصًا بنبض** من BotFather، ثم **قناة خاصة جديدة وخاوية**. زيد البوت مشرفًا بصلاحية نشر المستندات وتثبيت الرسائل. ما تعطيه حتى صلاحية فحسابات/مجموعات أخرى. ما تستعملش بوت ahdaf ولا ملف مستخدميه.
2. خذ معرف القناة الرقمي عبر أدوات تلغرام الموثوقة أو `getUpdates` ديال بوتك. ما تستعملش مواقع عشوائية كتطلب توكن البوت. صيغة القناة عادة `-100…`. ما تثبت حتى رسالة أخرى فهاد القناة المخصصة لنبض.
3. فمستودع GitHub: **Settings → Secrets and variables → Actions**:
   - Variables: `NABD_DATA_SOURCE=telegram` و`NABD_TELEGRAM_CHAT_ID` بالقيمة الرقمية الصحيحة.
   - Secrets: `NABD_TELEGRAM_BOT_TOKEN` بتوكن البوت الجديد. **رغم الاسم Secret، هاد المفتاح غادي يكون قابلًا للاستخراج من التطبيق النهائي.**
   - `EXPO_TOKEN` الموجود مخصص لنشر التحديث، ماشي بوت تلغرام. `NABD_API_URL` ما كيستعملوش الوضع المباشر.
   - ما تسيفط حتى مفتاح فالمحادثة أو PR أو commit.
4. بعد دمج PR، شغّل **App updates (OTA)** على `main`، أو **Android APK** للحصول على APK. النشر كيرفض وضع telegram بلا إعداد مكتمل؛ اختبارات PR ما كتاخدش أسرار البوت. ما تبدل حتى مكتبة أو إذن أصلي فهاد التغيير، لكن توافق OTA كيبقى مرتبطًا ببصمة runtime ديال APK المثبت، وماشي مضمون حتى يتفحص على الهاتف.
5. افتح التطبيق: وافق على المخاطر أولًا ثم اضغط **الاتصال وقراءة النسخة المثبتة**. حتى طلب Bot API ما كيدوزش قبل هاد الخطوة. الموافقة كتتعاود فكل تشغيل بارد، والتنبيه كيبقى ظاهر داخل التطبيق.
6. غير إلا كانت القناة جديدة فعلًا وما فيها حتى رسالة مثبتة، كيظهر زر **إنشاء نسخة جديدة** مع تأكيد منفصل. النسخة الأجنبية أو التالفة كتترفض؛ التطبيق **ما كيمسحهاش وما كيعوضهاش تلقائيًا**. هاد الزر ماشي لاسترجاع حسابات: إلا تحيد التثبيت بالخطأ رجّع النسخة الصحيحة يدوياً بدل إنشاء نسخة خاوية.
7. جرّب حسابين من جهازين: نفس الاسم مع يوزر مختلف، صورة مضغوطة، تسجيل الخروج والدخول، إغلاق وفتح التطبيق، منشور وتعليق وتفاعل. ما تنشرش لمستخدمين عامين بهاد الطريقة.

يمكن استعمال محادثة شخصية خاصة بدأتي فيها البوت بدل القناة، لكن خاص اختبار التثبيت والقراءة بها؛ القناة الخاصة المخصصة هي المسار الموصى به. التشغيل المحلي: انسخ `mobile/.env.example` إلى ملف محلي مهمل واضبط `EXPO_PUBLIC_DATA_SOURCE=telegram` و`EXPO_PUBLIC_TELEGRAM_BOT_TOKEN` و`EXPO_PUBLIC_TELEGRAM_CHAT_ID` ثم أعد بناء JavaScript. هاد الملف ما خاصوش يدخل Git.

## الرجوع أو الاسترجاع

- للتعطيل، رجّع `NABD_DATA_SOURCE=graphql` (مع API حقيقي) أو الوضع السابق، وامسح إعداد توكن الوضع المباشر من البناء، ثم انشر تحديثًا آخر. جلسات GraphQL السابقة ما كتتمسحش. **التعطيل ما كيحيدش التوكن من النسخ القديمة**؛ خاص تدويره أو إبطال البوت لوقف وصولها.
- للاسترجاع: وقف الكتابة من جميع الأجهزة، نزّل نسخة احتياطية مستقلة بأمان، اختار مستند `nabd-vault.json` السابق **من نفس البوت/المحادثة** وذو caption `nabd-direct-telegram-v1` وثبته يدويًا. راجع الحسابات والتغييرات المفقودة قبل إعادة التشغيل. استرجاع نسخة قديمة ممكن يعاود يفعّل جلسات قديمة ويلغي حسابات أحدث.
- البوت عنده حق الولوج لجميع النسخ القديمة؛ تدوير التوكن ما كيمسحش النسخ اللي تنزلات من قبل. الانتقال لاحقًا لخادم يحتاج خطة ترحيل مستقلة وموافقة، ماشي تبديل المتغير فقط.
- خادم `server/` وDocker/Compose باقين كبديل أقوى **اختياري**؛ ما كيدخلوش فهاد المسار المباشر، وملف Render الافتراضي تحيد. إعداد الحسابات بخادم موضح في [دليل الحسابات](accounts-and-avatars.md).

## التحقق وحدود الاختبار

```sh
npm ci --prefix mobile
npm run typecheck --prefix mobile
node --test mobile/tests/*.test.cjs
cd mobile && npx expo export --platform android
```

الاختبارات كتستعمل نقل Telegram مزيف، ماشي بوت حقيقي: الحساب والصورة واليوزر عبر عملاء جدد، التجزئة مقارنة بـ Node crypto، رفض النسخ التالفة/الأجنبية، منع مسح البيانات، تعارضات مختارة، فشل التثبيت، العزل عن GraphQL، وتنظيف ملف JSON المؤقت. **نجاحها ما كيثبتش اتصال بوت المالك، صلاحيات القناة، التحميل على هاتف حقيقي، ولا عدم ضياع تعديلات متزامنة.** ما تدار حتى استضافة أو مكالمة لبوت حقيقي أو نقل لحسابات أو نشر OTA خلال إعداد هاد الميزة.

### اختلاف أسماء الإعداد وعدم وصول التحديث

يدعم بناء GitHub أيضًا `TELEGRAM_BOT_TOKEN` أو `EXPO_PUBLIC_TELEGRAM_BOT_TOKEN` في Secrets، ومعرّف المحادثة تحت `NABD_TELEGRAM_CHAT_ID` أو `TELEGRAM_CHAT_ID` في Variables أو Secrets، و`EXPO_PUBLIC_TELEGRAM_CHAT_ID` في Secrets. يبقى اختيار `telegram` صريحًا عبر `NABD_DATA_SOURCE` أو `EXPO_PUBLIC_DATA_SOURCE` في Variables؛ الأسماء الأولى لها الأولوية. لا تنسخ مفتاح بوت تطبيق آخر لهذا الغرض. نتائج الفحص الفعلية، بما فيها اختلاف APK/OTA وما وصل أو لم يصل لمسار النشر، في [تقرير التشخيص](deployment-audit.md).
