# Meta6 Lab — تطبيق اختبار مستقل وخفيف

هذا **ليس نبض**، ولا يغيّر حساباته أو بياناته أو تحديثاته. معرّف Android مستقل:
`app.nabd.meta6probe`. لا Firebase/FCM في مسار الرسائل. لا SMS permissions.
كل الملفات كاملة تحت `lib/`، وملف الحزم `pubspec.yaml`، وملفات Android الكاملة
في `platform/`؛ سكريبت التحضير ينشئ Android scaffold ثم ينسخها بلا تعديل نبض.

## الواجهة الحالية — الفحص وتجربة المراسلة

شاشة واحدة داكنة وزر **تشغيل**. تعرض المضيفين المتاحين أولًا، وحالة HTTP
والزمن فقط، دون شروحات أو حوارات. أيقونة الرسائل في الأعلى تفتح تجربة Page
في شاشة منفصلة، بلا تبويبات في شاشة الفحص.
اتصال `mtalk.google.com:5228` يظهر منفصلًا تحت **اتصال TCP** ولا يُحسب موقعًا
أو دليلًا على وصول إشعارات FCM. نسخ التقرير متاح من أيقونة النسخ في الأعلى.

للتحقق من *6 استعملها وحدها: Wi-Fi مطفأ وبيانات الهاتف شاعلة، دون باقة/رصيد
إنترنت عادي. التطبيق يفحص الاتصال الموجود ولا يستطيع التحقق من عرض المشغّل
أو مجانية البيانات. كل جواب HTTP، حتى 400/401/404، يعني وصولًا فقط وليس
إذن API أو نجاح إرسال/استقبال. أخطاء DNS/TLS/الاتصال والمهلة تظهر «لم يصل».

الأيقونة هي الصورة التي قدّمها المستخدم كما هي، بلا قص أو إعادة رسم.
الأصل في `platform/launcher/source.jpg`، مع PNG بمقاسات Android وأيقونة adaptive.
إصدار 0.3.0+3 بنفس معرّف الحزمة ومفتاح الاختبار، للتثبيت فوق النسخة السابقة
دون مسح البيانات أو حذف نبض.

## اختبار إرسال واستقبال حقيقي — من الهاتف

الصورة المرسلة من المستخدم أظهرت HTTP 400 من Graph أثناء تجربة *6 حسب وصفه.
هذا دليل وصول في تلك الجولة، لا صلاحية API ولا نجاح تبادل الرسائل. CI لا يملك
بيانات Meta أو شبكة المشغّل، ولم ينفذ إرسالًا فعليًا إلى صفحة.

1. افتح أيقونة الرسائل ثم ترس إعداد الصفحة. أدخل **Facebook Page ID** وتوكن
   **صفحة اختبار فقط** على الهاتف. لا ترسل التوكن في المحادثة أو GitHub.
   `Recipient PSID` اختياري للاستقبال، ويمكن اختياره بزر «الرد» بعد وصول رسالة.
2. يلزم صفحة يديرها صاحب الاختبار وMeta developer app يدعم Messenger API،
   وPage access token بصلاحية `pages_messaging` وصلاحيات الصفحة المطلوبة.
   أثناء Development يلزم أن يكون مشارك الاختبار ضمن أدوار التطبيق؛ الحسابات
   الخارجية قد تتطلب App Review/Advanced Access. إعداد الحساب ليس آليًا هنا.
3. احفظ، ثم من Facebook/Messenger بحساب اختبار آخر أرسل نصًا فريدًا **للصفحة**.
   ارجع للرسائل في Meta6 وحدّث. التطبيق يجلب الرسائل أثناء فتح هذه الشاشة نحو
   كل 15 ثانية. لا يبدأ polling في شاشة الفحص.
4. اضغط **الرد** على الرسالة الواردة: يظهر PSID المختار فوق خانة الكتابة.
   اكتب ردًا واضغط إرسال. لا تُمسح الكتابة إلا بعد قبول Graph مع Message ID
   غير فارغ؛ الرفض يبقي النص. قبول Graph ليس إثبات أن الطرف الآخر قرأه.
5. تحقق من الرد داخل Messenger، وأرسل جوابًا جديدًا إلى الصفحة وتحقق من وصوله
   إلى Meta6. سجل نجاحًا فقط إن وقع التبادل الفعلي مع *6 وحدها بلا Wi-Fi/باقة عادية.

واجهة Settings قصيرة؛ التعليمات هنا وليست داخل التطبيق. التوكن مخفي ومحفوظ
في secure storage، ولا يدخل تقرير الشبكة. Page API صندوق صفحة اختبار وليس
backend عامًا لأي مستخدم نبض. نافذة وسياسات رد Meta تنطبق (غالبًا 24 ساعة).
`POST /v21.0/{PAGE_ID}/messages` يستخدم `messaging_type: RESPONSE` إلى PSID.
`GET /v21.0/{PAGE_ID}/conversations` يجلب
`messages.limit(10){id,message,from,created_time}` بحد 3 صفحات ×25 محادثة، وليس
أرشيفًا كاملاً. المهلة الكلية لكل طلب 8 ثوانٍ. Authorization في header، لا URL.
Graph FAIL في آخر فحص يوقف الإرسال والاستقبال؛ نجاح لاحق يتطلب فحصًا جديدًا.
لا SMS ولا نفق أو proxy ولا دمج مع نبض. لا توكن إنتاج داخل APK.

## المحلي وفحص الخلفية

SQLite يحتفظ بالتقارير والبيانات السابقة دون مسحها. التوكن السابق، إن وُجد،
يبقى داخل secure storage ولا يظهر في UI أو التقرير. بوابة النشر تتحقق من
SQLite والإشعارات والتخزين الآمن ومهمة Workmanager محلية حقيقية، دون طلب شبكة.
لا توجد أذونات SMS. الخلفية غير مفعلة افتراضيًا؛ يمكن تشغيلها صراحة في إعداد
الصفحة (محاولة نحو كل 15 دقيقة، وقد تتأخر تحت Doze/توفير البطارية). تُحفظ
رغبة المستخدم عبر إعادة التشغيل. مغادرة شاشة الرسائل توقف polling الأمامي.

مفتاح التوقيع مفتاح اختبار Expo العام، وليس مفتاح إنتاج؛ نزّل APK من هذا
المستودع فقط. المصدر لا يحتوي على توكن Meta حقيقي.

## 4) البناء من الهاتف — GitHub Actions جاهز

الملف الكامل: `.github/workflows/build.yml` باسم **Meta6 standalone APK**.
1. افتح مستودع GitHub من الهاتف ثم **Actions → Meta6 standalone APK → Run workflow**.
2. اختر main ثم **Run workflow**. لا تحتاج PC أو Flutter على الهاتف أو أسرار Meta للبناء.
3. بعد النجاح افتح **Releases**: نزّل `meta6-lab-arm64.apk` للهواتف ARM64، أو
   `meta6-lab-arm32.apk` لنظام Android ARM ذي 32 بت. يلزم Android 7 أو أحدث.
4. الإصدارات تشمل SHA256SUMS وpubspec.lock وstartup proof. ملفات Artifacts
   داخل workflow موجودة أيضًا لكن APK في Release أسهل من الهاتف.

CI: Flutter 3.35.7 وJava 17؛ pub get، تحليل، اختبارات HTTP/Graph/SQLite،
APK release مضغوط لكل ABI، ثم تشغيل x86_64 على Android فعلي داخل محاكي
للتحقق من فتح DB وتهيئة الإشعارات وتنفيذ مهمة Workmanager فعلية محلية بلا شبكة. لا توكن مضمّن في CI ولا إرسال
اختبار إلى صفحة حقيقية أو قراءة لصندوق حقيقي. النشر فقط بعد نجاح بوابة التشغيل.

لمن عنده Flutter: من `experiments/meta6_probe` شغّل
`bash scripts/prepare_android.sh` ثم `flutter test` ثم
`flutter build apk --release --split-per-abi --target-platform android-arm,android-arm64,android-x64`.


مصدر مفتاح الاختبار العام: Expo SDK 53 template،
`https://github.com/expo/expo/blob/sdk-53/templates/expo-template-bare-minimum/android/app/debug.keystore`.
`platform/public-test-key.base64` مجرد ترميز لهذا المفتاح العام؛ لا تستعمله لإنتاج.

بناء Workmanager يثبت حزمة الواجهة وتنفيذَي المنصتين معًا: الحزم الاتحادية
الحديثة ذات نطاق compatible غيرت signatures بشكل غير متزامن. compile/target SDK
يأتيان من Flutter 3.35.7 المثبّت (36)، مع بقاء minSdk 24. لا تدخل هذه التغييرات نبض.

أول تشغيل يسجّل مهمة فحص خلفية واحدة بلا HTTP أو SMS، للتأكد من تهيئة DB والإشعارات والتخزين الآمن في محرك الخلفية.



كل إصدار يُبنى من المصدر الحالي مع provenance وSHA256 لكل APK.
تشغيل Android والخلفية يظلان شرطًا مستقلًا للنشر؛ لا نعيد استعمال مرشح APK قديم.

المحاكي يستعمل Skia/software rendering لتجنب مشاكل Vulkan في تعريف SwiftShader؛ APK نفسه غير معدّل، وفحصه لا يثبت توافق GPU أو اتصال المشغّل في هاتف فعلي.

## الافتراضات — 3 أسطر
1. التجربة مستقلة على Android 7+ وتستخدم Facebook Page فقط، وليس Instagram Business في هذا الإصدار.
2. الفحص يستعمل الاتصال الحالي فقط؛ نوع الباقة ومجانية البيانات غير متحقق منهما آليًا.
3. شبكة *6 ونتائج إرسال/استقبال الهاتف لم تُختبر هنا؛ لا دمج في نبض ولا تفعيل SMS قبل نتيجة حقيقية ومراجعتها.
