# Meta6 Lab — تطبيق اختبار مستقل وخفيف

هذا **ليس نبض**، ولا يغيّر حساباته أو بياناته أو تحديثاته. معرّف Android مستقل:
`app.nabd.meta6probe`. لا Firebase/FCM في مسار الرسائل. لا SMS permissions.
كل الملفات كاملة تحت `lib/`، وملف الحزم `pubspec.yaml`، وملفات Android الكاملة
في `platform/`؛ سكريبت التحضير ينشئ Android scaffold ثم ينسخها بلا تعديل نبض.

## 1) تجربة *6 أولًا — بلا إعداد Meta

1. حمّل APK الخاص بـMeta6 Lab من إصدارات GitHub، وليس APK نبض.
2. طفي Wi-Fi، وأوقف باقة الإنترنت العادية. استعمل *6 وحدها على الهاتف نفسه.
3. افتح NetTest، اختر وصف الشبكة الذي ينطبق عليك ثم اضغط **Run test**.
4. اضغط **Copy results** وأرسل النص. لا يوجد توكن أو رسائل خاصة في التقرير.

الاختبار يستخدم Dio بمهلة كلية 8 ثوانٍ لكل HTTP request، وSocket بمهلة 8 ثوانٍ
لـ`mtalk.google.com:5228`. كل جواب HTTP، حتى 301/400/401/404/429/500، يعني
**REACHABLE فقط**. لا يعني صلاحية API أو مجانية البيانات أو نجاح إرسال رسالة.
التحويلات لا تُتبع؛ يُذكر المضيف المحوَّل إليه عند توفره. أجسام صفحات الويب لا
تُحمّل بالكامل. أخطاء الاتصال وDNS والمهلة وTLS تظهر FAIL.

إذا Graph FAIL تتوقف المراسلة حتى ينجح اختبار جديد. لا ندعي نجاح *6 ولا نفعّل
SMS أو نقرأ رسائلك الشخصية تلقائيًا. المرحلة التالية تُقرر بعد نتيجة الهاتف.
غيّر الشبكة؟ أعد الاختبار: النتيجة المحفوظة ليست ضمانًا للشبكة الجديدة.

## 2) إعداد إرسال/استقبال حقيقي — بعد نجاح Graph

يلزم **Facebook Page اختبار + Meta developer app + Page access token صالح**،
وليس توكن مستخدم عاديًا أو رقم WhatsApp. هذا API لصندوق صفحة، وليس خدمة
رسائل عامة بين أي مستخدمين. استخدم حسابين تجريبيين وصفحة خالية من البيانات الحقيقية.

من متصفح الهاتف (وضع سطح المكتب عند الحاجة):
1. أنشئ/اختر صفحة اختبار تديرها، وتطبيق Meta يدعم Messenger API للصفحات.
2. أعط حساب الاختبار دورًا في التطبيق أثناء وضع Development. اربط الصفحة
   بالتطبيق واستخرج Page access token مع صلاحيات المراسلة المطلوبة، خصوصًا
   `pages_messaging` وصلاحيات الوصول إلى الصفحة التي يطلبها Meta.
   الحسابات خارج أدوار تطبيق Development قد تتطلب App Review/Advanced Access.
3. أدخل **Page ID** و**Page token** داخل إعدادات Meta6 على هاتفك فقط، ثم احفظ.
   لا ترسلهما في المحادثة أو تقرير NetTest أو issue عام.
4. من Facebook/Messenger بحساب مشارك الاختبار، أرسل نصًا إلى **الصفحة**.
5. افتح قائمة الرسائل في Meta6 واضغط تحديث، أو انتظر نحو 15 ثانية والتطبيق مفتوح.
6. بجانب الرسالة الواردة اضغط **نسخ PSID للرد**، وألصقه في Recipient PSID بالإعدادات.
7. اكتب ردًا في Meta6 واضغط إرسال. Graph يجب أن يرجع Message ID حقيقيًا؛
   اقرأ الرد عند مشارك الاختبار ثم أرسل جوابًا جديدًا إلى الصفحة وتحقق من وصوله.

الإرسال: `POST graph.facebook.com/v21.0/{PAGE_ID}/messages` إلى PSID، نوع
`RESPONSE`. ليس نشر منشور Page ولا إرسالًا تعسفيًا؛ يلزم تفاعل المستخدم وتسمح
نافذة وسياسات Meta الحالية بالرد (غالبًا 24 ساعة للمراسلة القياسية).
الاستقبال: `GET .../{PAGE_ID}/conversations` مع
`messages.limit(10){id,message,from,created_time}`. لا تُتبع URLs مجهولة من paging؛
نستخدم cursor على Graph نفسه. التجربة محدودة بـ3 صفحات ×25 محادثة ×10 رسائل
حديثة لكل محادثة في الجولة، وليست أرشيفًا كاملاً لصندوق نشط كبير.

**شرط نجاح التجربة:** الإرسال والرد يصلان فعليًا مع *6 فقط. نجاح NetTest أو
HTTP 200 أو نجاح CI ليس اختبار مشغّل، وليس دليلًا على وصول الرسائل لهاتفك.

## 3) المحلي والإشعارات والخلفية

- SQLite يحفظ النصوص محليًا مع UNIQUE(page_id,message_id)؛ الرسائل لا تتكرر.
- Riverpod يعرض أحدث 300 رسالة محلية للصفحة الحالية مع RTL. الرسائل الأقدم
  لا تُحذف من DB. لا تُرفع أي رسائل من SQLite تلقائيًا إلى خدمات أخرى.
- اطلب إذن الإشعارات من الإعدادات. رفض الإذن لا يمسح الرسائل ولا يمنع القراءة.
- فعّل الخلفية واحفظ: Android Workmanager يحاول تقريبًا كل 15 دقيقة، وليس
  كل 15 ثانية ولا موعدًا مضمونًا تحت Doze/توفير البطارية/Force stop.
- لا نفرض NetworkType.connected: Android قد يعتبر *6 غير متحقق من الإنترنت
  بسبب حجب فحوصات Google. المهمة تحاول اتصال Graph نفسه بمهلات محدودة.
- التطبيق المفتوح يوقف timer عند الإغلاق للخلفية ويستأنفه عند العودة.
- انتهاء التوكن/401 ورفض الصلاحية وحد الطلبات لها حالات واضحة وbackoff محفوظ.
- التوكن محفوظ عبر Android Keystore/secure storage. هذا **لا يجعل توكن صفحة
  مشتركًا داخل تطبيق موزّع آمنًا للإنتاج**. config.dart يوضح TEST ONLY وإمكانية
  proxy صغير لاحقًا؛ هذا الإصدار لا يستعمل proxy ولا domain fronting أو نفق بيانات.
- مفتاح التوقيع هو مفتاح Expo/RN التجريبي العام المنشور، لإبقاء تحديثات تجربة
  الاختبار متوافقة. ليس مفتاح إنتاج أو سرًا؛ نزّل APK من هذا المستودع فقط.

## 4) البناء من الهاتف — GitHub Actions جاهز

الملف الكامل: `.github/workflows/build.yml` باسم **Meta6 standalone APK**.
1. افتح مستودع GitHub من الهاتف ثم **Actions → Meta6 standalone APK → Run workflow**.
2. اختر main ثم **Run workflow**. لا تحتاج PC أو Flutter على الهاتف أو أسرار Meta للبناء.
3. بعد النجاح افتح **Releases**: نزّل `meta6-lab-arm64.apk` للهواتف ARM64، أو
   `meta6-lab-arm32.apk` لنظام Android ARM ذي 32 بت. يلزم Android 7 أو أحدث.
4. الإصدارات تشمل SHA256SUMS وpubspec.lock وstartup proof. ملفات Artifacts
   داخل workflow موجودة أيضًا لكن APK في Release أسهل من الهاتف.

CI: Flutter 3.35.7 وJava 17؛ pub get، تحليل، اختبارات HTTP/Graph/SQLite،
APK release مضغوط لكل ABI، ثم تشغيل x86_64 على Android فعلي داخل محاكي
للتحقق من فتح DB وتهيئة الإشعارات وWorkmanager. لا توكن مضمّن في CI ولا إرسال
اختبار إلى صفحة حقيقية أو قراءة لصندوق حقيقي. النشر فقط بعد نجاح بوابة التشغيل.

لمن عنده Flutter: من `experiments/meta6_probe` شغّل
`bash scripts/prepare_android.sh` ثم `flutter test` ثم
`flutter build apk --release --split-per-abi --target-platform android-arm,android-arm64,android-x64`.

## الافتراضات — 3 أسطر
1. التجربة مستقلة على Android 7+ وتستخدم Facebook Page فقط، وليس Instagram Business في هذا الإصدار.
2. صاحب التجربة يملك صفحة/حسابات اختبار وتوكن وصلاحيات Meta المطلوبة؛ لا يوجد توكن إنتاج أو حساب مُنشأ آليًا.
3. شبكة *6 ونتائج إرسال/استقبال الهاتف لم تُختبر هنا؛ لا دمج في نبض ولا تفعيل SMS قبل نتيجة حقيقية ومراجعتها.

مصدر مفتاح الاختبار العام: Expo SDK 53 template،
`https://github.com/expo/expo/blob/sdk-53/templates/expo-template-bare-minimum/android/app/debug.keystore`.
`platform/public-test-key.base64` مجرد ترميز لهذا المفتاح العام؛ لا تستعمله لإنتاج.

بناء Workmanager يثبت حزمة الواجهة وتنفيذَي المنصتين معًا: الحزم الاتحادية
الحديثة ذات نطاق compatible غيرت signatures بشكل غير متزامن. compile/target SDK
يأتيان من Flutter 3.35.7 المثبّت (36)، مع بقاء minSdk 24. لا تدخل هذه التغييرات نبض.
